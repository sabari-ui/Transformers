How To Use This Guide

This page is written for curious learners who have seen the famous Transformer diagram and want to understand what each block actually does. You do not need to be an expert, but a little comfort with vectors, matrices, and probabilities will help the equations feel less mysterious.

Start here
Read the diagrams first. Let the shapes and arrows give you the story before you slow down for the equations.
Then deepen
Read the formulas as optional detail. The surrounding explanation tells the story first, and the equations are there when you want precision.
End goal
By the end, you should understand tokenization, attention, masking, cross-attention, decoding, training, and how this connects to modern LLMs.
Prerequisites
Helpful but not required: vectors, matrix multiplication, softmax, probability distributions, and the idea of a neural network learning weights from data.

As an AI enthusiast learning about transformers, you have likely come across this architectural image but may not have a clear picture of what it means and how it helps achieve such great things. This guide will break it down for you step by step.

The Big Picture

Let's start from the outside in. A transformer takes a sequence of tokens and produces another sequence of tokens. In machine translation — the original use case — it takes a French sentence and produces its English translation.

The transformer as a black box: French sentence in, English translation out.

Opening the box, we see two major components: an encoder and a decoder, connected by a bridge of contextual vectors. The encoder reads and understands the input. The decoder generates the output one token at a time.

The encoder stack processes the input all at once. The decoder generates output token by token, attending to both its own previous outputs and the encoder's context.

The key insight: the encoder processes all tokens in parallel and builds a rich contextual representation. The decoder consumes those representations and generates the output sequence one step at a time, autoregressive-ly.

Core tensor shapes
X: (batch, seq_len, d_model) Q, K: (batch, heads, seq_len, d_k) V: (batch, heads, seq_len, d_v) QKᵀ: (batch, heads, seq_len, seq_len) attention output: (batch, seq_len, d_model)

In this guide we use the sentence "The animal didn't cross the street because it was too tired" — a classic example that reveals why attention is so powerful. What does "it" refer to? The animal, not the street. A human knows this immediately. We'll see how attention figures it out.

Architecture families

The original 2017 Transformer used both an encoder and a decoder, but modern models often keep only the part they need. This is the easiest way to connect the classic diagram to real systems you hear about today.

Family What it keeps Best at Examples
Encoder-only Bidirectional self-attention Understanding, classification, retrieval BERT, RoBERTa
Decoder-only Causal masked self-attention Next-token generation, chat, code GPT, Llama, Mistral
Encoder-decoder Encoder, decoder, and cross-attention Translation, summarisation, text-to-text tasks Original Transformer, T5, BART
Same attention idea, different wiring. The task decides which Transformer parts are useful.
ENCODER — STEPS 1–6

Step 1 — Tokenization & Embeddings

1
Encoder · Input stage

Before any neural computation, the input sentence must be converted into numbers. A tokenizer splits the text into tokens — words, subwords, or characters depending on the vocabulary. Each token is assigned an integer ID by looking it up in a fixed vocabulary table.

Those integer IDs are then mapped through an embedding matrix — a lookup table of shape vocab_size × d_model. Each token maps to a dense vector of dimension d_model (768 in BERT-base, 12,288 in GPT-3). This is just a dictionary lookup — no computation yet.

Why embeddings?
Words like "king" and "queen" end up with similar vectors because they appear in similar contexts during training. The famous king − man + woman ≈ queen arithmetic emerges entirely from this lookup table — no explicit rules.
Token d₀ d₁ d₂ d₃ d₄ d₅ … d₇₆₇

Hover a row to highlight it. Values are illustrative — real embeddings are learned.

The embedding matrix — each token maps to a 768-dimensional vector. Shape: seq_len × d_model = 9 × 768.
Equation · Static embedding lookup
E = EmbeddingMatrix[token_ids]  →  shape: (seq_len × d_model)

Step 2 — Positional Encoding

2
Encoder · Position injection

Here's a fundamental problem: transformers process all tokens simultaneously. Unlike RNNs that read left-to-right, a transformer sees all tokens at once — meaning it has no built-in sense of order. "The dog bit the man" and "The man bit the dog" would produce the same embeddings without any positional information.

The solution: add a positional vector to each embedding. The original Transformer uses sinusoidal functions of different frequencies — each position gets a unique pattern of sine and cosine values across dimensions.

Sinusoidal PE formula
PE(pos, 2i) = sin(pos / 10000^(2i/d_model)) PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
Positional encoding is added (not concatenated) to the embedding. Each position gets a unique sine/cosine fingerprint.
⚡ Modern variants
Sinusoidal PE is fixed at training time. Modern models use learned alternatives: RoPE (Rotary Position Embedding, used in Llama) rotates Q and K vectors by position, enabling better length generalization. ALiBi adds a linear bias to attention scores instead. Both outperform the original sinusoidal approach.

Step 3 — Query, Key, Value (Q, K, V)

3
Encoder · Attention setup

This is where attention begins. Each token's embedding is projected into three different vector spaces using three separate learned weight matrices: Wᵠ, Wᴷ, Wᵛ.

Think of it as giving each token three different business cards:

Three learned projections from the same input X. d_k = d_model / num_heads (e.g. 768/12 = 64 in BERT-base).
Intuition
The Query is what you're looking for. The Key is what you offer to other queries. The Value is the actual information you carry. When Q matches K well (high dot product), that token gets a large portion of V blended into the result.

Step 4 — Scaled Dot-Product Attention

4
Encoder · The core mechanism

Now we score every token against every other token. For each query vector, we compute its dot product with all key vectors, scale by √d_k, apply softmax to get a probability distribution, then use those probabilities to blend the value vectors.

The attention equation
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V Step by step: Q: (n × d_k), K: (n × d_k), V: (n × d_v) scores = Q · Kᵀ → shape: (n × n) [every pair scored] scaled = scores / √d_k → prevents softmax saturation weights = softmax(scaled) → rows sum to 1.0 output = weights · V → shape: (n × d_v)

The scaling by √d_k is critical. Without it, dot products grow large in high dimensions, pushing softmax into regions with near-zero gradients — the model stops learning. With scaling, the variance stays at 1.

Complexity
Attention is O(n²·d) in both time and memory — quadratic in sequence length. For n=512, that's 262,144 attention pairs per layer per head. This is why long contexts (n=100k+) require Flash Attention or sparse variants.

Step 5 — Multi-Head Attention

5
Encoder · Parallel attention

Instead of one attention function over the full d_model space, we run h parallel attention heads over smaller subspaces of dimension d_k = d_model/h. Each head independently learns to focus on different relationships.

Click each head below to see what kind of relationship it typically specialises in:

← click a head to learn its role
Multi-head equation
headᵢ = Attention(Q·Wᵢᵠ, K·Wᵢᴷ, V·Wᵢᵛ) each head: (n × d_k) MultiHead(Q,K,V) = Concat(head₁,…,headₕ) · Wᴼ shape out: (seq_len × d_model)
BERT-base uses h=12 heads, each with d_k=64. GPT-3 uses h=96 heads with d_k=128.

Step 6 — Feed-Forward + Residuals + LayerNorm

6
Encoder · Per-token processing

After multi-head attention, each token's vector passes through a position-wise feed-forward network (FFN) — the same 2-layer MLP applied independently to every token. Its inner dimension is typically 4×d_model.

Two critical additions wrap every sublayer: residual connections add the input back to the output (preventing vanishing gradients, letting information skip damaged layers), and LayerNorm normalises the result to stabilise training.

Add & Norm: the input x is added back (residual) before LayerNorm. Same pattern applies after multi-head attention. This is applied N times for N encoder layers.
FFN + residual + LayerNorm
FFN(x) = max(0, x·W₁ + b₁) · W₂ + b₂ [ReLU or SwiGLU] output = LayerNorm(x + FFN(x)) also: = LayerNorm(x + MultiHeadAttn(x, x, x))
⚡ Pre-LN vs Post-LN
The original paper uses Post-LN (norm after adding residual). Modern models (GPT-3, Llama) use Pre-LN (norm applied to input before the sublayer). Pre-LN trains more stably without warmup and doesn't suffer from gradient explosion in deep networks.
DECODER — STEPS 7a · 7b

The decoder generates output tokens one at a time, autoregressive-ly. At each step, it has access to (a) its own previously generated tokens and (b) the encoder's full contextual output. It uses two types of attention to exploit both.

For the decoder and cross-attention diagrams, we switch to one translation example: "Je suis étudiant" → "I am a student". The animal sentence remains the running example for self-attention and coreference.

Step 7a — Masked Self-Attention

7a
Decoder · Causal attention

The decoder's first attention layer looks at its own generated tokens so far. But during training, we feed the entire target sequence at once (for efficiency). To prevent the model from "cheating" by looking at future tokens, we apply a causal mask.

The mask sets the upper triangle of the attention score matrix to −∞ before softmax. After softmax, those positions become exactly 0 — the model is blind to future tokens.

Causal mask — 5-token example

green = can attend · red = blocked (future)

Masked attention equation
scores = Q · Kᵀ masked = scores + M where M[i,j] = 0 if j ≤ i −∞ if j > i weights = softmax(masked / √d_k) output = weights · V
Token at position t can only attend to positions 0…t. This forces the model to generate each token without seeing what comes next — a requirement for autoregressive generation.

Step 7b — Cross-Attention (Encoder → Decoder)

7b
Decoder · The bridge

This is the layer that makes seq2seq translation possible — the bridge between the two languages. Here:

  • Q comes from the decoder's current English tokens (what English word are we generating?)
  • K and V come from the encoder's output (the full French contextual embeddings)

The decoder's Q asks: "what do I need from the French context right now?" The encoder's K and V answer that question. This lets every decoder step attend to any part of the source sentence.

Cross-attention: the decoder's Q queries the encoder's K and V. This is the only place the decoder "sees" the source sentence.
Architecture variants
Encoder-only models (BERT) have no cross-attention and no masked self-attention. Decoder-only models (GPT, Llama) have only masked self-attention — no encoder, no cross-attention. The full encoder+decoder architecture (T5, BART, the original 2017 transformer) is used for translation and summarisation.
OUTPUT — STEP 8

Step 8 — Output Probabilities

8
Output · Token prediction

The final decoder hidden state is projected to the vocabulary size by a linear layer. The raw scores are called logits, then softmax converts them to a probability distribution. The next token is picked by one of several decoding strategies.

Output projection + softmax
final_hidden: (d_model) Wᵒᵘᵗ: (d_model × vocab_size) logits = final_hidden · Wᵒᵘᵗ → shape: (vocab_size) e.g. 32,000 P(word_t) = softmax(logits) next_token = argmax(P) [greedy] or sample(P, T=temp) [sampling] or beam_search(P, k) [beam]

P(next token | "The animal didn't cross…") — top candidates:

1.0
The model assigns probability mass across the entire vocabulary (~32k tokens). Greedy decoding picks argmax. Temperature T<1 sharpens, T>1 flattens the distribution.
Weight tying
The output projection matrix Wᵒᵘᵗ (d_model × vocab_size) is often tied to the input embedding matrix — they share the same weights. This saves ~20-100M parameters and often improves performance because similar tokens get similar representations at both input and output.

How Transformers Learn

The architecture above describes the forward pass: tokens go in, probabilities come out. Learning happens when the model compares those probabilities with the correct next token, measures the error, and updates its weights through backpropagation.

A language model learns by predicting held-out tokens from context, then nudging its weights to put more probability on the correct answer next time.
Next-token objective
given tokens: x₁, x₂, ..., xₜ train target: x₂, x₃, ..., xₜ₊₁ logits_t = Transformer(x≤t) probs_t = softmax(logits_t) loss_t = -log P(xₜ₊₁ | x≤t) total_loss = average cross_entropy over all positions optimizer step: weights ← weights - learning_rate · gradient

Cross-entropy punishes the model when it assigns low probability to the correct next token. Backpropagation computes how each parameter contributed to that error, and gradient descent nudges the weights so the next-token distribution becomes slightly better on future batches.

Pretraining
The model sees massive text corpora and learns general patterns: grammar, facts, style, code, reasoning traces, and world regularities.
Teacher forcing
During training, the model receives the correct previous tokens, even if it would have generated a wrong token on its own.
Fine-tuning
After pretraining, models can be adapted for instruction following, chat, tool use, retrieval, safety behavior, or domain-specific work.

From The Original Transformer To Modern LLMs

Most chat and code models people use today are decoder-only Transformers. They repeat one simple loop: read the context, predict the next token, append it, and repeat. Scale, data quality, training recipes, and inference systems make that loop feel intelligent.

Key bridge
The classic Transformer explains the mechanism. Modern LLMs add scale, better positional methods such as RoPE, larger context windows, instruction tuning, reinforcement learning from feedback, retrieval, tools, and careful serving infrastructure.

Implementation mental model

Embeddings
A token embedding is a table lookup. The model learns the table, but inference just indexes rows by token ID.
Attention
Self-attention is mostly batched matrix multiplication: project Q/K/V, multiply QKᵀ, softmax, then multiply by V.
FFN
The feed-forward network is applied independently to each token position. Attention mixes tokens; the FFN transforms each mixed representation.
Inference loop
Decoder-only LLMs generate by repeating: run the model on the current context, sample one token, append it, and continue. A KV cache stores previous keys and values so each new token does not recompute the entire past.
Concept Why it matters
Context window The maximum number of tokens the model can attend to at once.
Scaling laws Performance tends to improve predictably with more compute, data, and parameters, though data quality and architecture choices matter enormously.
Prompting A prompt is just part of the token context. The model conditions its next token distribution on everything inside that context.
KV cache At inference time, previous keys and values are cached so the model does not recompute the entire context for every generated token.
The same attention machinery becomes much more powerful when trained at scale and wrapped in modern inference techniques.

Tokenization in practice

Modern tokenizers usually split text into subwords rather than full words. Methods such as BPE, WordPiece, and SentencePiece let a model handle rare words, names, code, and many languages with a fixed vocabulary. A word like unbelievable might become un + believ + able, depending on the tokenizer.

Decoding strategies

Greedy decoding always picks the highest-probability token. Beam search keeps several likely paths in parallel. Sampling methods such as top-k, top-p, and temperature trade determinism for variety.

Limitations And Responsible Use

Hallucination
A Transformer predicts plausible tokens, not guaranteed truth. Retrieval, citations, tools, and verification help reduce this risk.
Context cost
Attention grows with sequence length. Long-context models need memory-efficient kernels and careful prompt design.
Bias and safety
Models inherit patterns from training data and alignment choices. Evaluation should include fairness, robustness, and misuse risks.
Attention is not always explanation
Attention weights show where information is mixed, but they are not a complete proof of why a model made a decision. They are useful signals, not perfect explanations.
